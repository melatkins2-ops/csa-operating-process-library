No Wrong Door standard

RECEIVE → UNDERSTAND → ROUTE → CONFIRM → SUPPORT → CLOSE

Staff do not have to solve every issue. They do have to make sure the request reaches the right owner and that the handoff is confirmed.

Completion standard: the correct owner has accepted the connection, and the requester knows the next step. Forwarding an email alone is not completion.
Safety override: if an established emergency, crisis, suicide-prevention, safety, or mandated-reporting procedure applies, follow it immediately. No Wrong Door never delays or replaces those procedures.

Build or update a process

Use this guided builder instead of creating a separate SOP document. Start with the real work; the platform will route it through review and publication.

First: what are you creating? Choose SOP for a recurring department or CSA-wide process with meaningful operational importance; Procedure / Workflow for a detailed execution sequence; Tool / Job Aid for a checklist, decision tree, form, template, rubric, tracker, calculator, or quick guide. Choose Not Sure if you want CSA review to classify it.
Draft→Submitted→Department Review→Changes Needed→CSA Final Review→Published

Before you create something new

  • Search the Process Library first.
  • Ask whether this belongs inside an existing process.
  • Use a workflow or job aid when a full SOP is unnecessary.
  • Identify the role that owns the authoritative version.
  • Build around how the work should actually happen—not around a document format.

How publishing works

Contributors build or update the record here. Department review confirms operational accuracy. CSA final review checks alignment, handoffs, and the publication standard. Only the approved version becomes authoritative in the Process Library.

GitHub is the front door, not the database. This prototype stores builder submissions in this browser. The production connection should write these same fields to the shared CSA backend and approval workflow.
